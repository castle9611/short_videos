# 拾影 Android 安装包

应用名称：拾影。包名：`cn.shiying.studio`。版本：`1.1.2`（versionCode 10）。支持 Android 8.0 及以上，建议使用最新 Android System WebView。解析、素材、历史、设置分为四个页面，支持手机内置解析、原生直连下载、ZIP、3 路并发、记住下载目录，以及可关闭的剪贴板自动解析。

1.1.2 更换钴蓝色自适应图标，优化抖音、快手、小红书高清源选择。设置中的“保留下载历史”默认开启，记录新下载成功的文件（ZIP 记录压缩包）。关闭仅停止新增记录，不删除文件或已有记录。“历史”页可打开文件、仅清空记录，或确认后删除记录对应的文件；不会扫描或删除其他文件。旧版下载文件不会自动加入历史。

安装包下载：`https://shiying-api.castle9611-shiying.workers.dev/downloads/shiying.apk`。对应文件在 `web/downloads/shiying.apk`，仅作为网站下载资产发布，不会递归打包进下一份 APK。

## 包含内容

APK 内置界面和抖音、快手、小红书解析器，使用原生网络层直接访问平台。默认使用手机本地模式，无需账号、电脑或 Cloudflare 服务，但仍需联网访问作品。公开范围、签名链接和平台验证仍影响解析结果。APK 不包含 PHP、Node 或 Cloudflare 运行时。

“设置 → 解析方式”可手动切换云端或局域网服务。云端地址：

`https://shiying-api.castle9611-shiying.workers.dev`

手机本地模式无需登录。切换云端或局域网后，登录状态保存在应用私有 WebView 存储中，由对应后端校验 24 小时会话有效期。不同服务的令牌隔离保存。主页批量功能继续隐藏。

## 启动与剪贴板

每次冷启动或从后台返回应用时清空上次输入。默认开启“设置 → 启动行为 → 打开时识别剪贴板”：应用获得前台焦点后，识别抖音、快手、小红书分享链接，自动填入并开始解析。没有支持的链接时保持空白；正在解析或下载时不发起新的自动任务。

关闭开关后仍清空旧输入，但不会读取剪贴板。开关重启后保留。应用不持续监听后台剪贴板、不保存原始剪贴板文本；返回应用自己的保存/目录选择窗口时不触发重复解析。Android 可能显示系统剪贴板访问提示。

## 局域网服务

电脑运行 `./start.ps1`，手机与电脑连接同一局域网。在 APK 的“设置 → 解析方式 → 连接电脑服务”输入启动输出中的地址，例如 `http://192.168.21.3:8080`，点击“切换服务”。手机直接请求电脑的 PHP 服务，无需访问 workers.dev；电脑需要保持开机并运行服务。IP 变化后更新地址，局域网防火墙配置见 `scripts/enable-lan.ps1`。

服务地址保存到手机，重启后继续使用。云端和各个局域网地址的账号独立。HTTP 局域网请求由原生网络层发送，仅接受明确的 RFC1918 私网 IPv4 地址，拒绝外部 HTTP、用户信息、额外路径与跳转。WebView 仍禁止混合内容加载。手机本地模式不请求后端；云端/局域网模式的原生下载失败时回退到当前选中的服务。

## 下载

在“设置 → 下载目录”选择一个可写目录并授权。应用保存目录的持久授权，单项、ZIP 和逐个下载均自动保存到该目录，关闭或重启应用后仍有效。再次点击按钮即可更换目录；取消选择保留原设置。尚未设置目录时，首次下载会选择并记住文件夹。目录被删除或授权失效时，请重新设置目录。

APK 优先使用原生 HTTPS 直连平台 CDN，校验每次重定向的域名；云端/局域网回退令牌不会发送到 CDN。最多并发 3 个文件，下载数据临时写入应用缓存后保存到已授权目录；ZIP 也由原生生成，完成或取消后清理缓存和未写完的目标文件。媒体数据不经过 JavaScript 保存桥，旧 Blob 桥仅保留兼容用途。不申请相册、全部文件访问或外部存储权限。

已取消单文件 100 MB、ZIP 合计 150 MB 和旧保存桥 152 MB 的应用限制，也不再设置 15 分钟批次总时限。实际大小受剩余空间、文件系统和上游服务影响。网页 ZIP 使用 ZIP32 格式，超过其字段容量时提示改用 APK 或逐个下载，避免生成损坏压缩包。

## 构建

GitHub Actions → **Build Android APK** → Run workflow。签名后的安装包在构建产物 **Shiying-Android-1.1.2** 中。构建运行签名验证，并提供 SHA256 校验值。沿用本地 1.0.3 至 1.1.0 的签名，可覆盖升级并保留设置；旧签名 1.0.2 及更早版本仍需先卸载。

本地有 JDK 17、Android SDK 35、Build Tools 35.0.0 和 Gradle 8.11.1 时，可执行：

```sh
gradle -p android assembleRelease
```

需通过环境变量提供 `ANDROID_KEYSTORE_PATH` 与 `ANDROID_KEYSTORE_PASSWORD`。不把签名密钥或密码写入源码。

当前签名文件和密码保存在本地忽略目录 `.runtime/android-signing/`，GitHub 构建只使用仓库加密 Secrets。请妥善备份该目录，用于后续同包名覆盖升级；修改版本时增加 `versionCode`。不要提交或公开该目录。

前端有修改时重新构建 APK，即会打包最新网页文件。后端修改通过 Cloudflare 部署独立生效。

## 验证范围

构建应检查 Android 编译、APK 签名、包名/版本及前端资源完整性。JavaScript 测试检查下载桥、3 路图集并发、取消及错误处理；纯 Java 传输测试检查直连/代理回退、重定向限制、令牌隔离、文件完整性与大小限制。当前会话最近一次单条解析结果复用 2 分钟；切换账号、下载失败或过期时重新解析。没有连接真机时，登录、视频播放、系统目录选择及触控效果仍需在安装后验证。

## 可选实机下载检查

先在应用设置下载目录，再构建 `assembleRelease assembleReleaseAndroidTest`。安装两个 APK 后，可使用公开、有效的媒体直链运行：

```sh
adb shell am instrument -w -r -e url 'https://允许的CDN/公开媒体.mp4' cn.shiying.studio.test/cn.shiying.studio.DownloadCheck
```

检查在已授权目录下创建独立临时子目录，验证 3 文件原生下载和原生 ZIP，结束时删除该测试目录。测试刻意使用无效的代理令牌，只有手机直连实际成功才能通过。不要将测试 APK 当作正式安装包发布。

可额外传入 `-e server http://电脑IPv4:8080 -e share '公开分享链接'`，验证原生局域网请求、临时账号注册、鉴权解析与下载句柄。该检查会将测试手机切换到指定服务，测试账号不会写入 WebView 登录状态。
